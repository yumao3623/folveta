# Folveta 版本基线

历史基线日期：2026-09-18。**1.0.0 已冻结**，边界为仓库整理提交 `f37370a`；当前状态见 [项目状态](项目状态.md)。

## 1.0 的定义

以本次整理前的仓库节点 `3e0a51c` 及本次仓库整理为基础，将此前所有功能开发、视觉调整、性能修复和 SEO 实现统一视为网站 **1.0**。旧文档中的 v2、v3、v5 和阶段编号不再作为网站版本或待执行计划。

本基线说明 1.0 的历史代码范围。线上开关、第三方配置、收录与支付状态需要在执行相关任务时核实；版本命名不代表本次重新验收了所有线上服务。

## 网站定位

- 品牌：Folveta；正式域名：`https://folveta.com`。
- 主要用户：需要整理课程材料、准备复习的学生。
- 主要任务：上传材料，得到结构化、可核对来源的学习指南。
- 核心路径：上传 → 解析 → Study Guide → 可选 Quick Check → 返回相关知识点复习。
- 网站与搜索页面以英文为主；仓库说明使用中文。

## 产品边界

- 指南依据用户上传材料生成；来源引用用于核对，不代表内容或答案永远正确。
- 不承诺预测考题、覆盖整个课程或证明用户已经掌握知识。
- 扫描件、手写内容和仅含图片的图表可能无法可靠提取，需显示缺口。
- 当前没有音频、视频、URL、粘贴文本输入或开放网络检索功能。
- 演示指南不是用户生成结果，也不是教学效果或付费交易的证明。

## 版本规则

采用 `MAJOR.MINOR.PATCH`，以软件交付为依据：

- MAJOR：新的主要产品基线或明显的大阶段。2.0.0 沿用已确定的 SEO 第二阶段，正式收口为“可抓取、可使用、可验证的获客入口基线”，不是声称 SEO 排名已经成功。
- MINOR：完成独立、明确、可验收的产品里程碑，例如 2.1.0 的 Mock Exam 学习闭环。
- PATCH：已发布基线上的 Bug、小 UI、文案、SEO 配置和小性能修复；可以合并多笔提交后发布一次，不每次任务自动加号。
- 纯文档维护、目录提交、抓取/收录/审核等待及无软件变化的运维不产生版本号。
- 开发目标不等于正式版本。版本尚未验收时写“目标 2.1.0 / 实施中”，不声称已上线；package/lock 在准备正式发布时同步。
- 发布须有明确范围、适用测试、提交 SHA、生产部署回执与线上验证。验证成功后建立不可移动的 `vX.Y.Z` 标签；修复通过新提交与新版本交付，不能移动旧标签或改写历史。
- 本次建立规范前没有发布标签，不倒推虚构 2.0.1、2.0.2。`v1.0.0` 是回溯标记历史冻结边界，不表示今天重新验收其旧生产环境。

## 维护与发布流程

1. 任务开始读取项目状态与交接，核对工作区/分支和线上部署；按产品、修复、增长、运维或外部等待分类。
2. 实现与范围相符的工作，记录实际验证；不能把未执行的真实模型/支付检查写成通过。
3. 发布前运行 `npm run check` 与适用回归，核对迁移和回滚影响；push main 触发 Vercel 后检查对应 SHA，验证正式域名。
4. 已交付软件进入 Changelog，当前事实进入项目状态，后续目标进入路线图，平台回执只进外链清单；避免重复流水账。
5. 每次任务结束按 AGENTS.md 固定格式说明下一步和继续/新建对话，并给出可复制指令。

未来范围见 [路线图](路线图.md)，SEO 和目录等待分别见 [SEO 优化](SEO优化.md)、[外链清单](外链清单.md)。内部 generation-v2、数据库版本与网站版本互不替代。已合入 main 的旧远程分支只是历史引用，不代表并行维护的产品版本；不因整理文档擅自删除。
