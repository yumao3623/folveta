# Folveta 路线图

当前事实与下一步以 [项目状态](项目状态.md) 为准；这里只定义里程碑，不维护逐次任务流水账。未来只保留两个有产品依据的版本，反馈可改变顺序或范围。

## 2.0.0：SEO 与真实工具入口基线（收口）

为什么做：让海外学生能找到并实际使用 Study Guide Maker，消除页面只有营销文案、关键词归属不清与提交状态不可追溯的问题。

范围：既有 9 页技术 SEO、首页/PDF/方法页搜索意图与正文内链、PDF 页真实上传、可信结构化数据、Google/Bing 验证与提交、实际推广回执、可重复的 SEO 检查、长期项目交接。

完成标准：生产公共页面响应/canonical/robots/sitemap 正确；工具入口可用；相关测试和构建通过；部署与提交对应；平台的已提交、未提交、审核和排期可分辨；下一步有明确交接。

不包含：保证 Google 收录或排名、获得指定外链数、目录审核通过、完整 Mock Exam、批量长尾页、付费目录。外部等待不延长软件里程碑。

## 2.1.0：基于材料的 Mock Exam 学习闭环（下一目标，尚未开发）

为什么做：当前只有五题选择题 Quick Check，无法兑现用户确定的 Study Guide + Mock Exam Simulator 核心方向。

主要范围：复用已上传材料及来源定位，生成有覆盖说明的混合题型试卷；闭卷作答、计时、刷新恢复、提交与服务端评分；基于答案的弱项分析，回到相关材料并更新复习优先级。现有 Quick Check 和旧指南读取保持兼容。

完成标准：

- 用合成课程资料走通上传 → Guide → Mock Exam → 计时闭卷 → 提交 → 评分 → 弱项 → Priority 更新，并在桌面/移动浏览器验证。
- 题目与评分依据可追溯至上传材料；不预测真实考试、不生成材料外结论；主观题给出评分理由和不确定性。
- 提交前不泄露答案；服务端检查归属、考试状态与计时边界；重复提交、超时、刷新、生成失败及恢复有可验证处理。
- 数据迁移、权限、计费/额度和模型成本方案明确；隔离环境完成真实服务验证，再完成生产部署与受控验证；不把 Mock 数据测试当作模型/数据库验收。
- 对外首页、About、目录和相关 landing page 只在能力上线后更新；主关键词仍为 Study Guide Maker。

不包含：音视频/URL 输入、开放网络检索、预测押题、公开用户材料、课程商城、广泛学科程序化 SEO、自动代考。实施前先核对具体题型、计时和配额边界；这些属于设计工作，不是用户登录阻塞。

## 2.2.0：学习闭环的真实使用反馈与可靠性（候选，待 2.1 结果细化）

为什么做：目前缺少完整访问 → 生成 → 学习/测验完成的归因和真实用户证据；先测量流失和失败，再选择下一项优化。

主要范围：最小必要、符合现有隐私承诺的漏斗与错误观测；反馈入口；依据真实数据修复最高影响的失败或流失步骤；核对成本、恢复与移动端体验。

完成标准：事件定义与隐私说明一致，不记录学习材料正文/答案等私密内容；关键漏斗与错误可查看；至少一轮真实使用反馈形成有证据的优先级；选定问题修复并验证。若尚无足够用户样本，明确保持观察，不能宣称转化提升或为等待虚增版本。

不包含：为了埋点重构平台、广告投放、付费买链、保证增长比例、没有需求证据的大规模功能扩张。2.1 上线后再确定本版本的最终范围与是否值得启动。

## 与版本并行的维护

- 2.0.x / 后续稳定版本的 Patch：只在有具体修复和发布需要时创建，不预排补丁号。
- SEO/Growth：按相同时间窗口观察查询、索引、真实 referral；新页面需有独立意图和真实工具价值。
- 运维：部署故障、安全和数据损坏风险优先于路线图。
- 外部等待：Google/Bing 抓取、目录审核、Uneed 排期单独记录；没有变化不重复提交。
